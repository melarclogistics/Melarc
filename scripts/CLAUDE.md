# Root tooling (`scripts/`)

Node scripts, and the tests that hold the repository itself to its rules. Node runs them directly with type stripping (`node scripts/<name>.ts`): plain erasable TypeScript and imports written with `.ts`. They may use the root `devDependencies`, except the scripts CI runs before or without an install (`ci-aggregate.ts`, `ci-revision.ts` and `workflow-shapes.ts`, which they import): those import only Node built-ins.

## Rules

- Root tests run with `pnpm run test:root`, which names every test file (a glob would pass on zero tests). Add a new `*.test.ts` to that list or it never runs. `test-inventory.test.ts` fails when a test file of any package or of `scripts/` is run by no runner (`test:root`, a Vitest `include`, a Playwright `testMatch`), or a pattern matches nothing.
- `dependency-policy.test.ts` holds the manifests, `pnpm-workspace.yaml` and the lockfile to exact versions, no overrides, patches or pnpmfile, `allowBuilds` false only, and registry sources only. `gitignore.test.ts` asks Git which names are ignored and that no tracked file is.
- CI is [.github/workflows/ci.yml](../.github/workflows/ci.yml): five jobs and the `CI result` verdict. `ci-workflow.test.ts` fails when a mandatory command (it must be the whole script of its step, in the default shell and folder) or the aggregate wiring is dropped, a failure can be absorbed or skipped, a job leaves `ubuntu-24.04`, a trigger beyond push, pull request and manual run appears, or the browser tests stop running `chromium,firefox,webkit` (`MELARC_BROWSERS` and the install step); `workspace-pins.test.ts` holds the Node.js, pnpm and action pins. A new check goes into the workflow and `REQUIRED_COMMANDS`; a new job also goes into the aggregate's `needs` and command line. Never add `continue-on-error`, `|| true` or a condition that can skip a check. The runbook's [B0.8 notes](../delivery/planning/BOOTSTRAP_B0_RUNBOOK.md#carried-forward-from-b08) say what CI does not cover.
- Documentation is held to the repository. `local-setup.test.ts` checks [DEVELOPMENT.md](../DEVELOPMENT.md). `agent-docs.test.ts` checks every `CLAUDE.md`: at most 90 lines for the root file and 40 for an area file, the required root sections, links and commands, every top-level folder mapped, and every Markdown file reachable from a `CLAUDE.md`. A new Markdown file or folder must be linked from the root map or from a document it reaches.
- `setup-env.ts` (`pnpm run setup:env`) creates the git-ignored settings files. It never overwrites, prints no secret and writes each file whole or not at all.
- `package-source.ts` (`pnpm run package:source`) makes the ZIP for source review from what Git knows, refuses settings files, keys, dependencies and output by name, and fails if a local credential or a private key block appears inside a file it would pack, or a path cannot be unpacked on Windows and macOS (names differing only by case, device names, a trailing dot or space). It never changes the working tree and prints no value. Its ZIP writer is plain (65535 files, 4 GiB): do not add ZIP64 without a need.
- `design-contrast.ts` recomputes every ratio in the colour tables of [DESIGN_SYSTEM.md](../design/DESIGN_SYSTEM.md) §4.5 and §4.6 from the hex values the document names, and `design-contrast.test.ts` fails when a figure, a ✗ or a "thin" flag does not follow. Change a colour and its table together.
- `design-tokens.ts` holds [apps/ops-web/src/styles/tokens.css](../apps/ops-web/src/styles/tokens.css), the one executable token source, to the same document: every documented token exists with its value, the pairings the components use meet their contrast threshold from the file's own values, no colour is written outside the file, no `var()` names a property nobody defines, no stylesheet imports, loads from another origin, uses `!important` or redeclares a token, and every focus rule draws an outline (forced colours keeps outlines, not shadows). Change a token in the document and the file together.
- `eslint-rules.test.ts` runs the real `eslint.config.mjs` over snippets: the Ops Portal may not use raw network, web storage, `window.open`, HTML injection or `eval`, and no driver is given a connection string. Loosening a restriction fails it. `markdown-links.test.ts` fails on a relative link or anchor between tracked Markdown files that leads nowhere, and `repository-shape.test.ts` on Python tooling, a second package manager's lockfile or a tracked settings file.
- `infra-check.ts` (`pnpm run infra:check`) says whether PostgreSQL answers where the database tools look. It probes this machine only, sends no credential and changes nothing; its loopback rule is held to the API's by a test.
- Never write a check that passes when it has nothing to check.

## Tests

`pnpm run test:root` runs them all and needs no service.

# Attestation verifier (`apps/attestation-verifier`)

The private JVM service that decides whether a Rider handset's Android key attestation is genuine (S0.55; [SECURITY_DESIGN.md §15.2](../../architecture/SECURITY_DESIGN.md)). The API calls it from `completeRiderDeviceEnrolment` and from nowhere else; it holds no database credential and no application secret, and makes one outbound call, to Google's revocation list. It is a Gradle build, not a pnpm package: run it through `pnpm run verifier:test`, `verifier:build`, `verifier:start`, `verifier:stop` and `verifier:status` ([scripts/verifier.ts](../../scripts/verifier.ts)), which need a JDK 21 ([DEVELOPMENT.md](../../DEVELOPMENT.md#the-attestation-verifier)); `start` reads the git-ignored `.env` made from [.env.example](.env.example).

## Layout

- `service/src/main/kotlin/com/melarc/attestation/`: `PolicyVerifier` (the ten steps of §15.2.1, in order, on top of the library), `TrustData` (accepted roots and the revocation list: loaded at start, refreshed every 6 hours, retried every 15 minutes, usable for at most 24 hours from its fetch), `RevocationList` (strict parser and fetch), `VerifyRequestParser`, `VerifierServer` (`POST /v1/verify`, `GET /v1/status`, `GET /v1/metrics`), `VerifierConfig` (the `VERIFIER_*` settings), `Verdict`, `Telemetry`, `Main`.
- `service/src/test/`: `fixtures/` builds the adversarial chains from nothing but BouncyCastle's ASN.1 types (deterministic keys, RFC 6979 signatures: one chain for each way to be accepted and for each way to be refused, independent of the library they hold to account); then the policy, server, parser, configuration, trust-data, revocation-list and process tests, `RealChainsTest` (ten real device chains of the pinned release) and `DeviceKeyVectorsTest` (the device-key vectors the API consumes, regenerated on this JDK) and `AttestationVectorsTest` (the chains the API sends to this service in its own tests, a selection of these fixtures, regenerated with `./gradlew :service:attestationVectors` and held to a fresh run).
- `third_party/keyattestation/`: Google's library, vendored byte for byte ([PROVENANCE.md](third_party/keyattestation/PROVENANCE.md)). `gradle/`: the version catalogue, `verification-metadata.xml` (a checksum for every artifact) and the wrapper (its distribution held to a checksum). `fixtures/`: the real chains and the script that converts them.

## Rules

- No certificate parser, path validator or revocation check is written here: they are the library's, configured in `PolicyVerifier.libraryVerifier` with its own constraints switched off, so that the policy checks each one in the order and with the meaning of the design (exactly one package, _every_ signing digest approved, the hardware-enforced root of trust alone). A cause is a member of `IntegrityCause` and the API port's word for word; the API keeps `TRUST_DATA_UNAVAILABLE` apart from every verdict about a device.
- It fails closed: an unexpected exception while a chain is read is a refusal, trust data is judged before any evidence is read, and a list never loaded, older than the maximum age or from a roots file that never loaded is `TRUST_DATA_UNAVAILABLE`, which says nothing about the device. The package, the signing digests and the accepted roots are release inputs with no default; a debug signer is refused in production; beyond loopback, and in production, the caller must present its secret.
- Nothing a request carries is logged, counted or echoed: the log, the metrics and a refusal hold classes, closed causes, durations and field names of ours (`unknown_member`, never the caller's text), and a test scans for certificates, challenges, keys and the secret. A metric label is a member of a closed set this process names.
- A change to a policy step needs a fixture that fails without it (the mutants in the plan's record are the pattern); a change to the pinned library, a Gradle version or a dependency follows [PROVENANCE.md](third_party/keyattestation/PROVENANCE.md): read the diff, check every artifact against an advisory database, regenerate `verification-metadata.xml` from an empty file. BouncyCastle stays at 1.85 or later and Kotlin at 2.4.20 or later (`scripts/verifier-provenance.test.ts` says why).
- Never add a persistent store, a second outbound call, a framework, a test-only branch in `src/main`, or a way to skip the roots or the list. A new setting goes into `VerifierConfig.KEYS`, [DEPLOYMENT_AND_ENVIRONMENTS.md](../../architecture/DEPLOYMENT_AND_ENVIRONMENTS.md) and the API's matching setting together.

## Tests

`pnpm run verifier:test` runs Gradle `check`: the vendored sources against their checksums, the compiler and every test (about a minute; the first run downloads Gradle and the dependencies, each held to its checksum). The tests start no service of yours and need no database; `MainProcessTest` starts the built process on a free loopback port, and `DeviceKeyVectorsTest` runs `java` on `GenerateDeviceKeyVectors.java` and holds its output to the committed vectors ([the vectors and how they are made](../api/test/vectors/README.md)).
